# dotfiles

My dotfiles, managed with [GNU Stow](https://www.gnu.org/software/stow/).

## Layout

The repo root **mirrors `$HOME`**. `stow .` symlinks each entry into place
relative to `~` (e.g. `repo/.config/fish/config.fish` → `~/.config/fish/config.fish`).

Some directories must stay **real** (not symlinked) because the app writes
runtime state or secrets there. `install.sh` pre-creates these before `stow .`.
The full list is the source of truth — keep `install.sh` and `AGENTS.md` in sync.

## Install (fresh machine only)

    brew install stow fish        # macOS; use apt on Linux
    git clone git@github.com:daveyarwood/dotfiles.git ~/.dotfiles
    cd ~/.dotfiles
    ./install.sh

Run `install.sh` **before** launching apps that create their own config dirs.

## Warnings

- `stow` symlinks into the **live `$HOME`**. Do not run it on a machine you care
  about without knowing what you're doing.
- `stow` reads the **filesystem**, not git: a gitignored file that's physically
  present still gets stowed. Keep caches/artifacts out of the working tree.
- Configs are universal — OS-specificity lives *inside* the configs (e.g.
  `kitty.conf` includes the right `-macos`/`-linux` variant). No per-OS split.

## Notes

- `.gitconfig` is generated by `~/.bin/generate-gitconfig`, not tracked here.
- `bootstrap_ubuntu.sh` is a historical line-by-line install reference, not a
  script to run verbatim.
- `~/.config/fish/` is co-managed by [fisher](https://github.com/jorgebucaran/fisher):
  `conf.d/`, `functions/`, `completions/`, `themes/`, `fish_plugins` are
  fisher's. Only `config.fish` and `custom/` are in this repo.

See `AGENTS.md` for agent-facing working rules.
